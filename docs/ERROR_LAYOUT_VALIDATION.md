# 请求失败布局稳定性

登录布局的后续层级修复与当前验收标准见 [LOGIN_VISUAL_ACCEPTANCE](LOGIN_VISUAL_ACCEPTANCE.md)。下文“辅助动作占位”是057批次的历史方案，已由独立核心表单/后置反馈与条件次动作取代；表格及日志的记录不受影响。

## 范围与修复

仅 xui 的公开 React/原生组件及正式示例。不涉及产品后端、部署、用户本地电脑或持久化真实业务数据。

- DataTable 原来仅在已有行刷新/失败时插入反馈 grid track，确实会改变表头/主体位置。现为常驻 token 反馈槽；长内容只在局部滚动。零行加载、失败、空态使用同一个占位区，底栏计数不复用可变长度错误。
- 登录页原先只设反馈最小高度，长错误会扩大居中内容；辅助取消/核对会话动作的增减也会改变主按钮宽度。现在反馈区尺寸由公共 token 控制，完整错误在 Alert 内滚动；辅助动作占位，但不可用时从 a11y/Tab 排除；主动作闲置/忙文案都参与固有尺寸测量。
- API Key 与日志页保留局部状态区和取消动作位置。未知写入警告和恢复入口仍完整可达，不解除 write guard、不重放写入、不缓存 secret。
- 原生 API Key/结构化日志以前在每次状态通知时 append 所有现有行，业务日志在成功重读后重建整表。现在 keyed 行只在真正新增/换序/删除时操作 DOM；同一记录的请求失败和恢复保留动作节点及焦点。
- 两类日志详情的加载与失败也共享一个局部反馈区，避免无 payload 时重试令弹层正文高度反复变化。
- 正式 HTTP 示例同步采用公共反馈/辅助动作结构，用真实 fetch 覆盖网络故障。

## 授权与离线边界

仅保留宿主仍授权提供的当前 rows/data。401/403、认证撤销、租户/资源切换、卸载与瞬时秘密清理仍由原来的 owner/领域规则执行；本修复不添加绕过或另一个缓存 owner。成功登录、确认的新数据、主动切换页面/筛选等有语义变化的内容允许正常重排。

保证针对已加载的应用和资源。首次从未加载资源且完全离线不在可用性承诺内。核心 CSS 未使用远端字体/图标/CDN；宿主自配 logo、图片、延迟模块仍可能加载失败。没有加入 Service Worker、凭据缓存或自动重放请求。
