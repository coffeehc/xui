# 面向 Agent-ready 系统的视觉与交互研究

日期：2026-10-13。完整通用规范与所有默认值仍只在 [DESIGN](DESIGN.md)。本文记录参考取舍和验收方法，不建立第二套主题、字号、状态机或业务协议。

## 产品定位与本轮边界

系统首先具备可供Agent独立调用的业务API；UI是人观察状态和数据、直接操作、必要时介入Agent操作的入口。视觉目标是**简洁、明了、快速**：尽快看懂现在怎样、哪里有问题、能做什么、做完发生什么。UI不以聊天窗口、满屏渐变、闪光或“AI”装饰代替这些能力，也不把业务执行封装为只能点页面的流程。

本轮登录/管理员初始化是熟悉表单的第一样板，实际修改范围见[登录视觉验收](LOGIN_VISUAL_ACCEPTANCE.md)。下列通用验收要求指导后续公共组件；并不宣称已实现Agent执行台、暂停、撤销、审批、实时任务流或任何产品集成。不为展示增加不存在的业务能力。

## 信息、视觉与状态规则

### 可观察：默认界面先回答关键问题

- 默认未展开状态显示页面任务/对象、当前权威状态、会影响决策的关键异常和一个明确的主要操作。窄屏与放大时允许自然纵向滚动，但不能依赖展开高级区才发现阻断信息。
- `进行中`、`等待确认`、`已完成`、`失败`、`结果未知`是不同事实。客户端等待结束、超时、关闭窗口或收到建议都不能显示成业务完成。
- AI建议/草稿与已经执行的变更必须有文本区分。来源、更新时间、执行对象或作用范围在影响判断时可见；不要使用虚构的置信度、预计完成时间、进度百分比或审核状态。
- `0`只表示已确认的零；尚未加载/不可读/权限不足/未知不能格式化为零、空列表或成功。刷新时可保留旧结果，但要让用户知道它不是新的权威读数。
- 颜色辅助表达主次和风险，不单独承载状态。普通文本、辅助文字、焦点与控件边界遵守DESIGN对比规则；禁用样式不被当成“没有权限/失败”的唯一解释。品牌色不占用错误和成功语义。
- 标题、正文、标签、帮助、数字值使用既有文字角色，不因“科技感”压小文字。根字号、文字缩放和实际中文sans回退可验证；不在产品里用强制像素字号抵消用户偏好。

### 可操作：熟悉控件与及时反馈

- 主要动作描述具体意图，保持位置和可访问名称；相同范围内主次明确，危险操作不通过“确定”隐藏后果。进行中就地显示事实，不把按钮替换为另一个无关尺寸的面板。
- 用户触发后即进入已知的等待表现并阻止重复提交；只有权威完成才显示完成。允许取消本地等待时文案必须说明它不是撤销服务端操作。
- 标签始终可见，placeholder不能代替label。帮助解释格式、范围或后果，不重复标题或标签；必填/限制按真实合同表达，不给普通登录新增新密码规则。
- 初始未操作字段不展示责备式错误。提交时定位第一个可改字段；之后按实际校验时机更新。字段错误贴近并关联字段，整体错误靠近动作；缺乏权威结果时不猜“密码错误”或“已回滚”。
- 刷新/加载/离线/失败保留页面任务、有效输入、主体位置与可继续的动作；只在需要的局部反馈。认证秘密清除按AUTH合同，不能为了“保留输入”改变安全行为。
- 反馈有可见文本且可被读屏感知，避免每次普通轮询抢焦点或反复朗读同一状态。需要用户处理的错误保留足够时间，不只用瞬时toast或spinner。

### 可介入：真实能力与逐步展开

- 只显示真实可用的确认、修改、接管、重试、暂停、终止或撤销能力。没有能力时说明边界，不放假按钮；“暂停请求”“停止等待”“撤销已完成变更”不能混为一谈。
- 有后果的动作在执行前展示作用对象、范围和已知后果；执行后显示服务端已确认结果。未知结果说明当前不能安全继续什么、以及真实可用的核对路径；禁止自动重复写入来让界面“恢复”。
- 默认显示结果摘要与必要决策，技术细节/历史/原始数据/解释通过明确的展开入口查看。阻断状态、风险与必须选择的项不可藏在折叠区；展开和收起保留当前输入、滚动与合理焦点。
- 控制在键盘、触屏、窄屏与放大下均可达；展开按钮表达expanded，弹层支持既有关闭/回焦点合同。不得以hover-only提示、局部小滚动盒或不可见焦点作为唯一通道。

## 交付与后续范围

当前交付先完成同一个AuthPage的登录和管理员初始化视觉，保留已存在公共表单、主题、认证与setup owner。其余可观察状态、动作组合、渐进详情、Agent介入面板等列为后续公共组件设计；必须先盘点已有公开入口，再决定是否新增。产品API、业务状态机、权限、审批与执行能力归各宿主，不能由xui视觉规范替代或推断。

验收必须同时报告通过、失败、未测与证据来源。构建成功、静态ARIA、DOM模拟和旧截图都不能证明真实浏览器、真实读屏器、真实移动键盘或真实产品已通过。
