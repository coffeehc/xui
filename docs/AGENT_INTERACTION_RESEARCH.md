# 面向 Agent-ready 系统的视觉与交互研究

日期：2026-10-13。完整通用规范与所有默认值仍只在 [DESIGN](DESIGN.md)。本文记录参考取舍和验收方法，不建立第二套主题、字号、状态机或业务协议。

## 产品定位与本轮边界

系统首先具备可供Agent独立调用的业务API；UI是人观察状态和数据、直接操作、必要时介入Agent操作的入口。视觉目标是**简洁、明了、快速**：尽快看懂现在怎样、哪里有问题、能做什么、做完发生什么。UI不以聊天窗口、满屏渐变、闪光或“AI”装饰代替这些能力，也不把业务执行封装为只能点页面的流程。

本轮登录/管理员初始化是熟悉表单的第一样板，实际修改范围见[登录视觉验收](LOGIN_VISUAL_ACCEPTANCE.md)。下列通用验收要求指导后续公共组件；并不宣称已实现Agent执行台、暂停、撤销、审批、实时任务流或任何产品集成。不为展示增加不存在的业务能力。

## 风格提炼：清晰、克制、精确

**当前决策阶段：先评审风格概念图，再选方向。** 冷中性+克制蓝、精密紧凑与暖中性+青绿、温和专注是同内容比较的候选方案；概念图不是现有产品截图。以下映射用于说明已有token与设计取舍，不冻结候选配色，不授权继续批量修改风格代码。现有功能与缺陷验收继续；新的风格扩展等待用户选择。

这是根据用户对系统定位的思考提炼出的**设计建议**，用于本轮样板及后续评审，不表示用户已最终确认了风格或全部页面方案。可辨识度来自一致的主次、秩序与反馈，不来自为每个页面添加装饰。

- **清晰**：一眼能分清对象、状态、数据与下一步。首先看见任务标题、影响判断的事实和主要操作；说明贴着它解释的内容。放大以后仍然有同样的阅读顺序，不能只在宽屏截图中成立。
- **克制**：中性背景和表面承担大部分画面，强调色留给主要动作、选中位置与焦点。普通区域平整，借留白、对齐和必要细线分组；不把每段说明都包成卡片。错误出现时才获得相应语义强调。
- **精确**：标签说明对象，值说明事实，状态说明进展，动作说明能改变什么。同一含义使用同一形状、位置和词语；没有事实支撑就不画百分比、零值或完成勾。按钮按下、等待、失败和完成都有及时、局部、可理解的反馈。

### 可辨识的视觉语言与已有token映射

以下只指定角色组合，不重定义任何颜色、字号、圆角、间距或动画默认值。具体值与浅深配方始终由DESIGN生成。

| 视觉特征 | 现有角色与组合 | 取舍与检查 |
| --- | --- | --- |
| 温和中性底、安静表面、少量青绿强调 | `layer-canvas` / `layer-shell` / `layer-surface` / `layer-raised`；`foreground` / `muted-foreground`；主动作`action-primary`与对应foreground | 延续现有暖灰/青绿家族辨识，不换一套“AI色”。深色按成对角色转换，不机械反色；辅助文字仍满足可读性。 |
| 平整分组、清楚边界 | `surface-line` / `separator-line`、现有radius与`shadow-flat`；浮层才用`shadow-overlay` | 普通卡片不叠厚阴影，列表行不各自变成大卡片；边线区分区域，不用密网格包围每一条信息。 |
| 正文字体清楚，标题有层级但不压过任务 | `font-heading` / `font-sans`及`font-size-page-title`、`section-title`、`body-sm`、`body-xs`、对应line-height与字重 | 字体角色表达职责。帮助弱于正文，不能小到难读；统计值或独立登录任务可采用已声明的对应角色，不能把整页标题都放大为宣传标语。 |
| 对齐优先，疏密有节奏 | `layout-content-inset`、`layout-section-gap`、`layout-toolbar-gap`、`layout-field-gap`、`space-*`与组件现有宽度token | 同组紧、不同组有分隔；label/value/action靠近所属对象。留下阅读和操作空间，不用空白撑满视口，也不把所有区域压成同一密度。 |
| 主动作明确，次动作易找 | 既有Button variants；`interaction-selected` / `interaction-hover` / `interaction-pressed` / `interaction-focus`、control-height与focus tokens | 主要操作有最强但局部的对比；次动作使用较轻表现；危险动作表达真实后果。强调色不能同时装饰所有图标、标题和边框。 |
| 状态色小范围、文字不可缺 | `status-info` / `warning` / `success` / `error`的foreground、soft、line组合 | 状态贴对象或操作，不把全页染成红/绿；unknown不能借绿色包装为安全完成。必要异常可提高优先级，平常不常驻大色块。 |
| 反馈快而短，主体不晃动 | `motion-duration-fast` / `motion-duration` / enter/exit与既有easing、press-scale；reduced-motion角色 | 颜色/按压/局部出现说明反馈，不用反复脉冲、漂浮或长开场动画表现“智能”。执行速度不能靠动画假装；减少动效仍立即显示状态。 |
| 熟悉图形、恰当数据表达 | 现有control-icon-size、图文间距、`chart-color-*`与chart-axis/grid角色 | 图标辅助识别，不替代重要文字。序列色不等于任务状态色；无真实可比较数据时不放装饰图表。 |

这套语言不等于“越少越好”：必须保留可见标签、必要帮助、错误原因、恢复路径和可操作范围。也不等于“越紧越快”：长任务的概要与重点可以稀疏，重复列表可以紧凑，但点击区、焦点和阅读尺度不能被密度牺牲。

### 三个公共页面如何体现同一种风格

#### 1. 登录与管理员初始化：一个明确的任务焦点

阅读顺序：品牌身份 → 任务标题 → 简短说明 → 常显字段标签/输入 → 主要操作 → 原位反馈。登录使用已实现的公共AuthPage窄单框；setup复用同一owner，仅按真实任务增加字段及新密码说明。

- 中性页面承托一层平整表面，主动作是唯一主要强调色面积；品牌不是第二个大标题。
- 标题说明“登录”或“创建管理员”，不再重复品牌全称；帮助解释下一步而非添加营销口号。
- 输入、标签、按钮同一阅读轴，间距表达所属关系；错误在操作附近，busy在原位置，未知结果明确阻断而不是诱导重试。
- 当前源码样板已按此结构修改，定量值和验收在DESIGN/LOGIN_VISUAL_ACCEPTANCE。像素是否真正平衡、中文字体是否正确、状态是否稳定，必须以本轮安全CI真实截图复核；不能仅凭结构宣称成功。

#### 2. 数据列表：先找到对象，再判断和操作

设计说明，未在本轮新增页面或业务组件。复用现有PageHeader、SearchToolbar、DataTable及DataRegion能力；宿主提供列、权限、请求与操作。

信息优先级：页面任务/范围与必要状态 → 搜索及主要动作 → 列表对象、关键值和状态 → 与对象相邻的行操作 → 分页/结果范围。高级筛选通过已有展开入口获取，不占满默认第一屏；已生效筛选及会改变解读的限制仍须可见。

- 与登录同用中性底、清晰文字、局部强调；搜索和创建等主要动作不与每一行的次操作争抢。
- 对象名、状态、关键值和更新时间形成稳定列关系。状态贴近对象；只有当前异常使用状态语义，不给所有数字加大色块。未知total不写成0。
- 表格本身是信息组织结构，不把每行再包多层Surface；用既有行、表头、分隔、选中/hover表现浏览与选择。
- 刷新保留可用行并标注事实，不整页清空再跳回；排序、筛选后的空结果解释当前范围，不能冒充权限不足或加载失败。
- 窄屏先保障对象/状态/动作可理解；必要多列表格沿公开region水平滚动，不能裁掉操作。此例不要求擅自隐藏业务列或替换表格模型。

#### 3. 任务详情：看清进展和结果，必要时介入

设计说明，未实现新的Agent任务控制台。可先组合PageHeader、公开Section/布局、DataRegion与Disclosure/Accordion；具体领域API和状态属于宿主，不新增假暂停、撤销或审批。

信息优先级：任务对象/范围与权威状态 → 当前需要人判断的异常或待决事项 → 与该状态匹配的主要操作 → 结果/当前关键数据 → 按需展开的执行记录、解释和原始数据。

- 首要事实和可介入动作在同一上下文，用户不用在日志里找“现在怎么了”。没有需介入事项时，结果摘要和关键值成为视觉主角，不强行放一个大按钮。
- `进行中`、`等待确认`、`结果未知`和`已完成`有不同文字；AI生成的建议明确是建议，只有权威回执支持已执行标记。局部状态色指向这条事实，不把整张页面变成“运行灯”。
- 先用平整概要和清楚的小标题组织状态、结果、上下文；详细时间线/解释在其后或折叠区。不要把每一个底层事件都绘成聊天气泡，也不让高频日志挤动上方操作。
- 当前操作区域仅列真实允许动作；有后果的介入先说明对象、影响和已知限制，完成后就地显示结果。缺少能力时给真实边界，不提供不可兑现的“接管”。
- 同一文字、表面、状态与focus角色贯穿登录和列表；差别是信息密度与任务结构，不另造任务页专用配色或动画语言。

### 风格复审：除了“测试通过”还要看什么

1. 把三页默认态并排看：是否明显同一家族，且能立即指出每页主要任务/事实？如果只能靠logo识别，说明层级、间距或控件语言尚未统一。
2. 去掉品牌素材与装饰：对象、状态、主动作是否仍易找？如果需要背景大图或动画才能成立，任务焦点仍不清楚。
3. 同页的idle/busy/error/unknown并排看：主体顺序是否一致，强调是否只随着重要性而变化？观察异常是否太隐蔽或占据整屏。
4. 检查中文实际字体和长内容：标题不挤压标签，标签不依赖placeholder，帮助不因弱化而不可读；未截断关键后果或动作。
5. light/dark/system、320/390、根字号200%与真实浏览器200%分别查看。稳定几何、可达动作与四边焦点是底线，不能以“截图更紧凑”为理由放弃。

本轮初步建议是先保留当前中性+青绿家族、平整表面和熟悉控件，将辨识度落在层级、对齐和真实状态反馈上；暂不另调全局配色或增加AI装饰。待登录/初始化新截图通过可读性与比例复核后，再用列表与任务详情验证同一语言能否成立，而非先批量翻新全部页面。

## 信息、视觉与状态规则

### 可观察：默认界面先回答关键问题

- 默认未展开状态显示页面任务/对象、当前权威状态、会影响决策的关键异常和一个明确的主要操作。窄屏与放大时允许自然纵向滚动，但不能依赖展开高级区才发现阻断信息。
- `进行中`、`等待确认`、`已完成`、`失败`、`结果未知`是不同事实。客户端等待结束、超时、关闭窗口或收到建议都不能显示成业务完成。
- AI建议/草稿与已经执行的变更必须有文本区分。来源、更新时间、执行对象或作用范围在影响判断时可见；不要使用虚构的置信度、预计完成时间、进度百分比或审核状态。
- `0`只表示已确认的零；尚未加载/不可读/权限不足/未知不能格式化为零、空列表或成功。刷新时可保留旧结果，但要让用户知道它不是新的权威读数。
- 颜色辅助表达主次和风险，不单独承载状态。普通文本、辅助文字、焦点与控件边界遵守DESIGN对比规则；禁用样式不被当成“没有权限/失败”的唯一解释。品牌色不占用错误和成功语义。
- 标题、正文、标签、帮助、数字值使用既有文字角色，不因“科技感”压小文字。根字号、文字缩放和实际中文sans回退可验证；不在产品里用强制像素字号抵消用户偏好。

### 可操作：熟悉控件与及时反馈

- 主要动作描述具体意图，保持位置和可访问名称；相同范围内主次明确，危险操作不通过“确定”隐藏后果。进行中就地显示事实，不把按钮替换为另一个无关尺寸的面板。
- 用户触发后即进入已知的等待表现并阻止重复提交；只有权威完成才显示完成。允许取消本地等待时文案必须说明它不是撤销服务端操作。
- 标签始终可见，placeholder不能代替label。帮助解释格式、范围或后果，不重复标题或标签；必填/限制按真实合同表达，不给普通登录新增新密码规则。
- 初始未操作字段不展示责备式错误。提交时定位第一个可改字段；之后按实际校验时机更新。字段错误贴近并关联字段，整体错误靠近动作；缺乏权威结果时不猜“密码错误”或“已回滚”。
- 刷新/加载/离线/失败保留页面任务、有效输入、主体位置与可继续的动作；只在需要的局部反馈。认证秘密清除按AUTH合同，不能为了“保留输入”改变安全行为。
- 反馈有可见文本且可被读屏感知，避免每次普通轮询抢焦点或反复朗读同一状态。需要用户处理的错误保留足够时间，不只用瞬时toast或spinner。

### 可介入：真实能力与逐步展开

- 只显示真实可用的确认、修改、接管、重试、暂停、终止或撤销能力。没有能力时说明边界，不放假按钮；“暂停请求”“停止等待”“撤销已完成变更”不能混为一谈。
- 有后果的动作在执行前展示作用对象、范围和已知后果；执行后显示服务端已确认结果。未知结果说明当前不能安全继续什么、以及真实可用的核对路径；禁止自动重复写入来让界面“恢复”。
- 默认显示结果摘要与必要决策，技术细节/历史/原始数据/解释通过明确的展开入口查看。阻断状态、风险与必须选择的项不可藏在折叠区；展开和收起保留当前输入、滚动与合理焦点。
- 控制在键盘、触屏、窄屏与放大下均可达；展开按钮表达expanded，弹层支持既有关闭/回焦点合同。不得以hover-only提示、局部小滚动盒或不可见焦点作为唯一通道。
