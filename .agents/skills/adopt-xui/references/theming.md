# 根据项目设计生成 xui 主题

用户可以直接说：**根据 DESIGN.md 生成 xui 可识别的 theme.css。** 目标是把项目视觉要求映射到实际 xui 版本的公开 CSS 变量，产出一份集中覆盖文件并接入现有样式入口。该短指令只授权主题及必要入口接入；不触发完整页面、布局、组件、API、认证或后端迁移。

项目 `docs/DESIGN.md` 可以包含页面信息层级、业务流程和私有组合约定；本流程只读取并落实其中的视觉差异。公共基线与项目约定需显式读取，Markdown 不自动合并；theme.css 未覆盖的变量继承 xui 默认值。关系见 [设计文件与主题](../../../../docs/DESIGN.md#项目设计文件与主题的关系)。项目组件/页面设计进入 [主技能的对应流程](../SKILL.md#项目组件与页面设计)，不因这些内容出现在设计文件中就扩大纯主题任务。

## 确认设计与公开合同

- 在采用项目读取适用 AGENTS.md，检查工作区、依赖锁定和已有样式入口，保护已有改动。设计来源默认是该项目的 `docs/DESIGN.md`；用户指定其他 DESIGN.md 时使用指定文件。xui 仓库的 [docs/DESIGN.md](../../../../docs/DESIGN.md) 是公共变量与默认值合同，不替代产品自己的设计文件。
- 先确定项目实际消费的 xui 版本、固定 SHA 或本地依赖路径，核对 manifests/exports、正式 CSS、[公开入口](../../../../docs/PUBLIC_API.md)及对应版本的 [实施合同](../../../../docs/ADOPTION.md#组件层次与扩展原则)。当前 checkout 的新变量不能直接当成旧安装版本的能力；不自动升级依赖或改 xui 公共合同。
- 读取产品设计中影响颜色、字体、尺寸、边线、层级、阴影和动效的要求，映射为当前版本真实存在的语义或必要组件变量。没有产品差异的角色继承 xui；不复制整份默认色板、完整 DESIGN 或库源码。设计文件缺失时先利用可核实的项目品牌、现有设计材料和 xui 默认值推进，说明缺失与采用的假设；只有决定性信息缺口才澄清。

## 生成或更新一份 theme.css

沿用项目现有样式目录和命名，生成或更新其中一份 `theme.css`。若已有同责主题文件，优先原位整理，保留无关修改，不另造第二份主题来源。用该文件的简短注释或现有采用记录保存设计来源、xui 版本/SHA，以及覆盖项的理由、浅深值和受影响控件；推导出的浅色或深色配对须与设计原文给定值区分。

- 覆盖放在 `@layer product-overrides`，作用于与默认变量相同的文档根，遵守实际版本的层序及 `data-theme` 合同。共享尺寸/字体可放在根规则，颜色按浅深分别定义，并覆盖 `system` 对应的媒体分支；不要只改 light/dark 而让跟随系统回到默认品牌。保持默认依赖方向，检查变量是否实际被消费及是否形成循环。
- 主色必须成对考虑 `--action-primary` 与 `--action-primary-foreground`；核对继承的 hover、pressed、selected 和 focus 的可读性。背景、文字、状态和浮层按各自语义映射，不能把状态色全替换为品牌色。少量主色差异无需重写整个主题。
- 尺寸使用 `rem` 或依赖公开尺度的 `calc`；字体覆盖保留中文、系统字体和通用字体回退。保留字体缩放、行距和文字下限；不通过缩小根字号修复布局。边线等单位按 xui 合同处理。
- 项目私有组合已有消费的自有语义变量可以在项目主题中集中定义，标明项目归属并核对消费位置；它们不属于 xui 公开 token，不要求 xui 内置。不要为尚未实施的组合发明未消费变量或借纯主题任务新增组件。
- 保留键盘焦点、错误反馈、必要对比、forced-colors 和 reduced-motion；不覆盖 accessibility 层使其失效。使用真实公开变量，不编造 xui 缺失 token，不用 xui 内部选择器、复制公共控件皮肤或 `!important` 实现设计差异。公共控件现有公开能力表达不了的要求才作为 xui 缺口报告，写出需求和当前受限位置；项目领域专属视觉仍由项目负责。

## 接入现有入口与单一主题 owner

在项目已有应用样式入口导入这份文件，并核对公开 xui 基础 CSS 的唯一加载方式与层序，避免重复导入、未分层旧全局 CSS 或旧颜色规则接管最终值。项目尚未采用 xui 时，只建立使该主题可被消费所需的公开主题入口；沿用项目依赖管理方式，不能把主题任务扩大为全量包、页面或协议升级。

复用已有与 xui 合同兼容的单一文档主题 owner，支持 `light` / `dark` / `system`，区分用户 mode 与实际 effective 结果。默认公开 runtime/init 在sessionStorage保存主题选择，同一标签页刷新保留，不读取或迁移旧localStorage；必要时用受控 bridge 接入宿主偏好；保留存储 key、格式和其他字段。首屏初始化先于可见内容，共用同一 owner；不再创建另一套 React context、storage 或 matchMedia 监听，不在 JS 保存调色板，不因换主题重置业务状态。

主题 CSS 不能统一浏览器/OS 自绘的选择面板。若发现裸 select、datalist、日期弹出面板或产品私有 xui 皮肤补丁，列出准确文件位置、影响与对应公开替代：简单选择默认 SimpleSelect / bindSelectControl，复杂选择采用 Select/Combobox 或公开原生搜索组合，date-only 选择采用 Calendar / createCalendar，输入与动作采用 Input / Button 等。Calendar 不等于现成 DatePicker 或时间选择器，缺失组合如实记录；NativeSelect 等显式平台 API 与安全文件选择窗口属于能力边界，不作为普通项目控件的默认推荐。仅当本次另有统一组件授权时迁移；theme-only 范围内保留并报告准确位置和迁移建议，不顺手改业务控件或布局。公共封装内部继续保留真实 input/button 的表单和可访问语义。

## 验证与交付

运行采用项目的实际构建，并在真实代表页面核对最终导入链、computed style 与覆盖变量的实际效果。至少覆盖浅色、深色、system 随系统变化，以及窄屏和 200% 真实浏览器缩放；检查长中文/字体回退、主操作与输入状态、浮层、键盘焦点和 reduced-motion。根据覆盖项选择有代表性的页面与控件，不拿 xui 示例构建替代采用项目验收，也不为纯主题任务增加无关后端迁移检查。

交付说明 `theme.css` 与入口位置、设计和 xui 版本、关键映射/继承项、推导或无法表达的差异，以及构建和页面验证证据。构建、源码检查、现场验证分别报告；无法运行浏览器或特定模式时明确未验项，不把静态检查当成实际通过。完成后结束主题流程。
