# 接入与升级 xui

## 先确定范围与参考根目录

先解析本 SKILL.md 的物理路径，再从其所在目录向上三级定位 xui 根；全局发现入口可以是符号链接，不能从链接所在目录推算仓库。下文相对链接均以本物理 skill 目录为基准。

先按用户目标选择执行范围；“仅接入xui”和“接入xui+baseservice”决定前后端授权，不意味着每次都执行整项目迁移。

| 本次目标 | 执行范围与按需阅读 |
| --- | --- |
| 首次整体接入、明确的全量迁移 | 授权范围内所有页面/入口；读取[完整接入细则](references/full-adoption.md) |
| 指定版本升级、组件或页面改造 | 先查固定版本差异和调用点，只处理受影响实例及必要共享回归；执行下方定向流程 |
| 接入自查、设计评审 | 按受影响范围只读核对并报告，不因此获得实施授权 |
| 仅生成/更新项目主题 | 读取[主题流程](references/theming.md)，完成主题和必要入口后结束，不扩展组件、API或后端迁移 |
| 项目组件与页面设计 | 执行下方设计流程；仅设计请求以方案为完成，不升级依赖或修改业务 |

未指定范围的“仅接入xui”/“接入xui+baseservice”首次实施仍完成当前项目所需的完整接入；普通版本升级按合同差异选择范围，不能只改锁文件，也不自动重跑所有页面。共享主题、Shell、认证或构建入口有实质变化时，将其所有实际受影响页面加入范围并说明原因；影响未查清不能当作无影响。

## 共同边界

- 先读采用项目规则、工作区、已有设计/接入记录及本次版本差异，保护已有修改；不因参考公共库而修改公共库或其他项目。Git、基础设施及外部操作遵循当前项目授权，不在skill另设规则。
- 从[固定产物流程](../../../docs/ADOPTION.md#固定产物与可运行示例)核对目标SHA、manifest/SHA256SUMS/sourceGeneration、三包和锁文件；使用正式ESM/CSS/types/init，无源码alias，React/ReactDOM/Base UI保持宿主单实例。产品验收不能由库示例替代。
- 产品UI使用React公共组件，runtime只用公开TypeScript服务/模型/工具。保留宿主业务、权限、路由、HTTP/auth/resource/Controller owner和已有自定义主题；只清理本次被公共能力替代的竞争实现。具体边界见[接入手册](../../../docs/ADOPTION.md#组件层次与扩展原则)。
- 只有明确的联合接入授权才执行后端接线；定向任务有此授权时只读[联合服务接线章节](references/full-adoption.md#联合服务接线仅接入xuibaseservice)，不展开全量页面迁移。普通升级不迁移认证、业务协议或后端；默认client的服务前置不匹配时如实报告，不新增前端兼容层规避合同，见[宿主边界](../../../docs/ADOPTION.md#宿主边界)。
- 公共组件缺陷、缺失slot或增强请求按[归属规则](../../../docs/ADOPTION.md#接入合规与公共缺口归属)列举并交给xui；不得复制、fork、patch或穿透私有DOM/CSS。继续完成不依赖缺口的工作，不宣称适用失败项已通过。

## 定向升级与自查

1. 按[范围选择](../../../docs/ADOPTION.md#按影响选择执行范围)列出本次版本变化、全部受影响页面/组件实例/运行入口及必要共享回归。没有变化的登录、导航、主题、后端和其它API不重新迁移；只读自查沿用同一范围但不实施。
2. 只读取固定版本中命中的DESIGN、COMPONENTS、PUBLIC_API、ADOPTION和验证限制章节，不通读全部专项。选择[适用检查ID](../../../docs/ADOPTION_CHECKLIST.md#使用与报告规则)，无需遍历整表给无关项逐条填“不适用”。
3. 按[layout/slot映射](../../../docs/ADOPTION.md#逐页建立-layout-与-slot-映射)记录每个受影响实例的内容、正式slot/part、文字/色彩角色、状态、滚动/焦点owner和检查ID；按[反馈归属](../../../docs/DESIGN.md#反馈位置与保留时间)检查页面级临时通知走公共Toast、持续状态保留所属入口，不以show/hide整块提示挤动内容。已正确接线保留，不复制公共皮肤或重复表单/请求。
4. 实施后运行项目必要的类型/构建和受影响测试，按[实际页面验收](../../../docs/ADOPTION.md#实际页面验收)验证局部状态、布局、焦点及真实请求；有临时通知时执行TOAST-005～006，检查出现及自动/手动关闭后的原内容几何、节点和交互连续性。共享产物/依赖证据同一构建验证一次并引用；每个页面自身的slot和请求接线仍分别验收。全套unit/browser、冷启动或无关模块回归只在项目规则、实质变更或失败证据要求时扩大。
5. 按[交付条件](../../../docs/ADOPTION.md#交付与完成条件)在项目既有记录中保存范围、固定产物、逐实例矩阵、通过/失败/未跑/有依据的不适用、证据和公共缺口。相关检查通过且无未解决问题后完成交付，不重复同一验证；环境不足则明确部分完成。

### StructuredLogExplorer 定向升级

本次使用或升级完整StructuredLogExplorer时，读取[专项流程](references/structured-log.md)，按现有QueryForm/QueryField和LOG-QUERY-001～008执行；不要加载完整接入细则或将其展开为全项目迁移。组件内部slot和重置/清除动作的合同仍只由引用文档定义。

### 默认完整页面

本次涉及管理员初始化、登录、业务日志或平台API Key时，读取[默认页面专项](references/default-pages.md)。业务已启用且无已确认特殊要求时直接用公共完整页，经app/pages配置和公开slot接入，官方BaseService合同直接连接，不自行拼页面、改接口或增加前端兼容层；初始化缺口交BaseService，不猜默认端点。

## 项目组件与页面设计

读取项目自己的设计和当前页面，按当前AGENTS中的前端设计路由核对信息披露和说明文案；不把公共默认值当作产品事实。按[首屏信息架构](../../../docs/DESIGN.md#首屏信息架构与信息密度)、[公共页面组合](../../../docs/DESIGN.md#高信噪比页面组合)、[表单](../../../docs/DESIGN.md#表单和响应式)、[刷新](../../../docs/DESIGN.md#数据刷新与视图连续性)及[私有组合边界](../../../docs/DESIGN.md#项目私有组合组件的设计方法)确定任务、主次、动作、状态owner和容器。

给出本次需要的信息结构、真实公开组件/slot映射和关键状态样本；稳定项目约定更新既有设计章节，不复制公共规范。实施授权存在时用公开组合保留业务能力，按当前范围验证；仅设计/评审时给出方案或证据后结束。需要生成theme.css时再读取主题流程。
